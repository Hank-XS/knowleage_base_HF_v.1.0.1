# 知识库分类与文档接入

## 分类规则

统一使用「系统 / 知识库 → 工程 → 文件」作为归属关系，资料用途、版本、主题标签是独立字段。

| 字段 | 规则 | 示例 |
| --- | --- | --- |
| 所属系统 / 知识库 | 必选，使用业务系统名称；可在上传时新建，同层不能重名 | 账户核心系统 |
| 工程 | 代码工程必填，支持选择已有名称或创建；文档可关联已有工程，也可归入系统通用资料 | AccountBatch |
| 资料类型 | 自动识别为代码工程或文档，不用标签代替 | 工程 ZIP / DOCX |
| 资料用途 | 文档必选：需求说明、设计说明、接口规范、操作手册、业务规则、参考资料 | 接口规范 |
| 版本 | 必填，最多 32 字符，由上传者明确填写 | v1.0、2026-10 |
| 主题标签 | 可复用或新建；去除首尾空白、合并重复空白，同次上传忽略大小写去重；最多 12 个，每个最多 32 字符 | 账户、日终、对账 |

用途用于统计和筛选；标签补充业务主题，不承载格式、系统、工程等已有字段。一个工程可以关联多个文档，一个系统也可以保存通用文档。

主题标签没有固定预设词表，可选择已有项或输入后回车新增。只有随资料成功入库后，才进入下次上传的候选；候选来自当前有效资料，最后一份使用它的资料被移除后，不作为独立词表项保留。

## 上传与查找

- 上传资料页区分「文档资料」和「代码工程 ZIP」。右侧统一选择归属、用途、版本和主题标签，不再暴露切片、打标等处理配置。
- 上传后显示每个文件的处理结果和错误原因，支持直接查看结果；多个文档共用本次填写的分类。
- 知识库列表按整包展示代码工程，文档逐份展示。系统、工程、用途、类型和标签均可筛选，统计随筛选范围变化。
- 工程内的文件以保留目录的路径展示，支持搜索、分页，再进入具体文件的切片。
- 切片查看支持系统、工程、文件、版本选择，原文与切片并排展示，点击切片定位原文，并可下载对应版本原文件。DOCX / PDF 的原文面板是提取后的阅读正文，下载保留原始二进制文件。
- 图谱按系统、工程、版本和标签筛选，默认展示文件关联；需要时切换结构细节。悬停节点会高亮并提示可点击查看。超出显示范围会提示继续筛选。
- 「构建与治理」「接入任务」入口隐藏，原代码及接口保留。

## 图谱、版本对比和引用映射

- 切片和版本对比页独立提供左侧文件浏览器，按系统、工程、主题标签筛选后直接展示文件；选中文件在右侧查看详情。搜索和翻页作用于可见列表，切换筛选会清除旧文件选择及旧搜索条件。知识库原有跳转入口保留。
- 映射和图谱页的文件候选列表采用下拉内搜索、滚动加载，移除页面上没有可见列表对应的外置分页。允许从全部资料开始查找；选择系统后工程、标签、版本及文件逐级收窄，切换父级会重置下级选择。
- 图谱使用 SVG 渲染，重建时销毁旧实例，拖动时停止运行中的布局，避免 Canvas 局部刷新或旧布局残留形成重影。
- 图谱默认显示「文件关联」，将内部实体投影到所属物理文件，直接观察文件间 CALL、COPY、字段引用；「结构细节」保留程序、段落、字段视图。文件可作为关联中心，关联节点可继续居中或跳转原文。
- 当前有效工程之间自动匹配静态字面量 CALL 和 COPY 与唯一同名定义。优先本工程及同系统；跨系统的唯一静态匹配需主动开启显示。紫色虚线表示跨工程关系，点击关系可查看源工程、目标工程、行号和匹配依据。旧上传从保留的解析结果读取引用，新上传成功后自动参与匹配，无需重新上传旧工程。
- 同名冲突和动态调用不自动推断关系。自动关联只针对各工程当前有效版本，历史版本保持原始快照关系；目标版本替换或节点清理后，关联随当前状态更新。这些关系表示静态引用匹配，不代表已验证的运行时依赖。

- 图谱可选择系统、工程、工程版本和单独文件。文件模式默认展开文件结构，可选择是否带出相邻文件的一跳关系；相邻文件节点使用虚线边框。
- 实体类型来自解析结构：代码文件对应物理文件，程序对应 PROGRAM-ID，段落 / SECTION 和字段对应文件内部结构。Copybook 引用按照解析器的引用节点统计，同一 Copybook 可以出现多次，不能直接作为 Copybook 文件数。
- 关系线默认显示「包含、调用、引用 Copybook、引用」等文字，同向的同一对节点存在多种关系时合并显示文字。三元组列表仍保留每条关系。
- 版本对比和代码文档映射统一使用「系统 → 工程 → 文件」筛选，文件支持搜索和分页。代码比较按同一系统、工程及相对路径跨上传快照查找实际版本，不自动创建演示版本。
- 旧对比页曾自动追加演示版本；升级时仅将受该行为影响的代码文件预览指回实际上传版本，原有版本记录保留。
- 代码到文档、文档到代码均根据文档中的程序名、文件名引用检索。匹配限制在同一系统、本工程或系统通用资料中，结果可以跳转原文与切片。这是名称引用匹配，尚未进行业务语义映射确认。

## 上传进度与清理

- 上传页显示每个文件的真实传输字节数和百分比，工程传输完成后继续显示解压、解析、切片整理、结果入库四个实际阶段。文档解析期间显示处理状态，不推算无法测量的解析百分比。
- 切片页可删除单个切片，或清理所选文件版本的全部切片。知识库列表提供工程版本 / 文档版本的切片、图谱清理入口。
- 图谱总览可清理所选文件或工程版本的图谱。文件清理只删除该文件拥有的节点及关联边，不删除相邻文件节点；清理范围包含当前隐藏的字段、段落，包含完整范围而非画布截断后的部分节点。
- 操作前显示预计删除数量并确认。执行时重新核对预览，范围变化则要求重新预览；清理失败会恢复已移除的索引或图谱。需要 dev / gov / admin 角色。
- 切片清理同步移除检索索引，图谱清理独立执行；源文件和版本正文保留。知识库统计、切片页和工程解析结果同步显示清理后的数据。恢复已清理数据需要重新上传解析。

## 版本规则

- 工程以「系统 + 工程名称」识别，同一工程每次解析生成独立快照。默认列表、文件选择和检索采用最近上传且解析成功的有效快照。
- 新工程版本解析期间或失败时，已有成功版本继续可用。列表显示正在更新或更新失败，不增加一条重复的当前工程。
- 勾选「显示历史工程版本」查看历史快照。同一工程、同一版本重新上传成功后，替换该版本的旧图谱及检索条目；历史任务结果保留。
- 文档以「系统 + 关联工程 / 系统通用 + 文件名（含扩展名）」识别。不同工程中的同名文件互不覆盖。
- 新版本成为当前版本，历史正文、切片和原文件保留。同版本重新上传会替换该版本；使用新版本号才能保留两个独立版本。
- 文档只将当前版本纳入图谱和向量检索；历史正文、切片和原文件可在切片页面选择版本查看。

## 文档解析与切割

文档只支持 DOCX、文本型 PDF、UTF-8 Markdown，单个文件不超过 25 MB。不支持旧版 DOC 和扫描 PDF 的 OCR。

1. Markdown：识别 ATX / Setext 标题、段落、列表、管道表格和围栏代码块，保留正文位置及标题路径。
2. DOCX：按正文顺序读取标题、段落和表格，提取列表文字，保留标题路径；表格整体保存，不按固定行数拆散。页眉页脚、批注和文本框等非正文内容不在本次提取范围。
3. PDF：逐页提取文字，记录页码，清理可识别的重复页眉页脚及页码，识别常见编号标题和对齐表格。纯图片 PDF 明确提示先 OCR；部分无文字页会给出提醒。复杂多栏、跨页表格和视觉阅读顺序依赖原 PDF 的文本结构，需要人工抽查。
4. 按标题边界组合正文，约 1800 字符作为组合目标；完整段落、表格和围栏代码块允许超过目标，不硬截断。遇到表格或代码块单独成片。
5. 保存归一化正文偏移、标题路径和 PDF 页码，供预览和溯源使用。入库失败时恢复该文档之前成功的图谱及检索条目。

代码工程按 CodeGraph 识别到的结构生成切片，未识别结构的文件使用文件兜底切片。检索索引还会生成关联原始父块的子片段；检索行为描述用于召回，最终依据保留原始正文和位置。

## 数据预处理与质量记录

上传入口先进行格式、路径、压缩体积和编码检查，再统一文本换行符和 BOM。COBOL 的列位置、缩进、注释和物理行序保持不变，不套用历史测试数据集中的程序名、文件名黑名单。空白源码、二进制伪装、非法控制字符、明显编码损坏及未解决的合并冲突从解析输入中隔离，并记录文件和原因；若没有可用源码则拒绝任务。非法压缩路径、符号链接、加密包及超限压缩包仍整体拒绝。

重复文件按规范文本 SHA-256 标记，保留不同物理路径及其引用身份，不能因为同内容就删除程序或把同名程序随意绑定。文档重复正文保留原始位置并给出质量提醒，问答阶段对重复证据去重。原始 ZIP、DOCX、PDF、Markdown 保留；清洗结果的质量记录保存在工程报告或文档版本元数据中。文档标题路径、正文偏移和 PDF 页码继续用于溯源。

入库前校验嵌入向量的数量、维度一致性和数值有效性；工程按批次调用嵌入服务，避免一个切片一次网络请求。嵌入或发布失败不激活新版本，保留之前可用的知识。质量检查不是业务正确性审计；TODO、未实现段落和正常注释不作为脏数据删除。

代码工程 ZIP 支持 `.cbl/.cob/.cobol/.cpy`，上限 50 MB，解压总量 200 MB、最多 5000 个条目、20 层目录，单个 UTF-8 源码不超过 1 MB。支持 UTF-8 和 GB18030/GBK；EBCDIC 需先转换。已识别的 SECTION、段落及数据定义按完整结构范围生成切片，不设 100 行上限；缺少可切片结构时保留文件兜底策略。动态调用、JCL 和完整 SQL 表读写语义未覆盖。

## 问答与历史

默认展示简明答案，结论优先；补充说明和来源通过“补充说明与依据”打开，工具执行记录不在普通页面展示。未接入生成模型时明确提示演示模式，展示检索到的原文依据。

直接输入业务问题或粘贴代码，后台自动区分来源定位、相似实现与业务问答，无需选择模式。精确代码定位保留字面量、比较符和语句边界；相似实现会比较结构与条件，不能据此认定行为等价。程序名与文件名不同仍可查找；同名对象有歧义时需要补充系统或工程。

默认使用原文匹配、BM25 和可用的语义向量做融合排序，图谱补充明确的引用与调用关系。Demo 关闭模型重排；模型及索引配置见 [安装与启动](CodeGraph安装与启动.md)。当前版本与文档可见性在检索和原文预览中生效；文档可见性策略不等同于完整多租户授权。

引用对应实际原文位置，同一文件同一版本的重叠证据合并，不同版本分别追溯。静态调用关系不证明运行时必然执行；没有证据时说明本次无法确认。引用编号校验不代替业务事实的人工复核。

可在回答旁提交有帮助、知识缺失、引用错误或答案错误反馈；反馈进入待复核状态，不会自动将模型回答变成已验证知识。

左侧按最近更新展示当前账号的会话，支持搜索历史问题、分页、重新打开并继续追问。首次发送才创建会话，空会话不占列表；刷新恢复最近的已保存会话。历史读取和提问接口验证会话归属。

## 安装与升级

更新后在后端环境执行 `pip install -r requirements.txt`，新增依赖为 `python-docx` 和 `pypdf`。前端重新构建，后端重启后生效。

启动时为旧数据库补充分类字段。已有工程结果根据原始任务编号恢复系统、工程和版本归属，保留现有源码与切片，不触发重新解析。

当前仍采用单进程后端和本地基础向量索引。分类信息保存在文档、工程任务、切片及索引元数据中；不额外建设独立的标签治理或项目管理模块。
