某行核心系统迁移知识库 — 详细设计文档

项目 内容
文档名称 某行核心系统迁移知识库详细设计文档
版本 V1.0
日期 2026 年 10 月
依据 《汇丰银行核心系统迁移知识库技术方案》V1.0；《某行需求分析文档》V0.1；现有 Demo 工程 kb-system

1. 设计目标与范围

1.1 目标

支撑「AI 梳旧 → 建知识库 → 解耦评估 → 分布式重构迁移」路径，交付可私有化部署的迁移知识库：

  1. 迁移有依据：结论可追溯到源码行或文档定位符。
  2. 重构可验证：新旧行为差异可测、可登记。
  3. 知识可沉淀：结构事实靠解析器，语义靠大模型，最终确认靠人。

1.2 四个月交付边界

纳入本周期 不纳入本周期（后续）
CardDemo / ATM 全链路 Demo（2 周内） 全行千万行全量知识化
解析扩展（JCL/SQL/CICS/常量传播）MVP 运行时 SMF/CICS 监控全量接入
知识生成流水线（分层 Agent）+ 自动核验 领域模型微调
审核工作台 + 来源/置信度 多国家/地区细粒度数据主权隔离深化
GraphRAG 问答、影响分析、基础可视化 完整 CBM Lens 产品化改造
增量更新与版本快照 MVP 大规模并行重构工厂
1 个试点模块 Java 骨架生成 + 规则级等价性样例 生产并行切流

1.3 设计原则（与技术方案一致）

原则 设计落点
结构事实靠解析器 调用/读写/作业绑定仅由 parser 写入；LLM 不得增删调用边
语义解释靠大模型 功能说明、业务规则候选、流程图在结构事实约束下生成
最终确认靠人 review_status 门禁；未确认知识不可作迁移依据

1.4 与现有工程映射

技术方案层次 本工程模块（现状/目标）
① 数据接入 ingest/pipeline.py、hf_data/、知识管理上传 API
② 确定性解析 ingest/parsers.py、code_tree.py；扩展 codegraph fork
③ 知识生成 ingest/tagger.py、support_annotate.py、PI Agent 流水线
④ 核验 治理工作台 + 规则引擎（本期补齐）
⑤ 存储 Neo4j / Milvus / PG / MinIO；Demo 可回退 SQLite/文件图
⑥ 服务 FastAPI /api/v1/*、MCP Tools
⑦ 应用 前端问答/治理/影响分析/知识管理

2.2 端到端数据流（关键约束）

  1. 解析产出 结构事实 JSON → 写入图（source=parser）。
  2. 结构事实注入 Agent 上下文 → 生成知识文档 / 规则候选。
  3. 自动核验（关系一致性、出处存在性、Mermaid 边合法性等）。
  4. 失败/低置信 → 审核队列；通过 → 可检索；专家确认 → 可作迁移依据。
  5. 问答优先检索 review_status ∈ {auto_passed, confirmed}；影响分析 仅图遍历，LLM 只整理报告。

2.3 在线问答推理形态

阶段 形态 说明
Demo / 前 6 周 单一 Flow 问题分析 → 指纹分流 → 多路检索 → 重排 → LLM 综合 → 溯源作答
中后期可切换 Agent 动态编排 同一套 Tools（search_knowledge / graph_query / read_source），不重构工具层

3. 数据接入与解析设计

3.1 数据源与适配器

类别 内容 适配器 ID 优先级（Demo）
代码资产 COBOL、copybook、JCL/PROC、CSD、BMS、DDL code_cobol / code_jcl / code_csd P0
技术文档 架构、接口、运维手册 doc_tech P0
业务文档 SRS、流程图、规则说明 doc_biz P1
映射/报文 mapping、错误码表、样例报文 mapping / errcode / message P0（ATM）
工单 缺陷/变更 ticket P2
运行时（可选） SMF、CICS 监控 runtime P3

接入流水线：scan → parse → clean → tag → review → merge → index，任务状态落 PostgreSQL（Demo 可用 SQLite）。

3.2 代码解析

3.2.1 基础能力（codegraph fork）

  • tree-sitter COBOL：Program / Paragraph / PERFORM·GO TO / CALL 字面量 / COPY / 数据项 / EXEC CICS LINK·XCTL（字面量）。
  • 固定版本、关闭遥测、断网容器运行。

3.2.2 大型机扩展（本期必做）

扩展 输入 输出事实
SQL 表访问 EXEC SQL … END-EXEC Program -[:READS|WRITES|UPDATES]→ Table
文件↔JCL FILE-CONTROL / OPEN + DD Program -[:READS|…]→ Dataset，含 ddname/mode/dsn
JCL/PROC JOB/EXEC/DD、PROC 展开 Job-HAS_STEP-JobStep-RUNS-Program、BINDS Dataset
CICS CSD/BMS 交易定义、屏幕宏 Transaction -[:ENTRY]→ Program
动态调用常量传播 MOVE 常量链 → XCTL/LINK 变量 XCTL/LINK 边 + resolved_by=const_propagation；无法解析标 dynamic_unresolved

3.2.3 事实记录格式（示意）

{
  "job": "INTCALC",
  "step": "STEP15",
  "pgm": "CBACT04C",
  "binds": [
    {"ddname": "ACCTFILE", "dsn": "AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS", "disp": "SHR"}
  ],
  "source": "parser",
  "evidence": ["CBACT04C.cbl:42-44", "INTCALC.jcl:STEP15"]
}

3.3 文档解析

  • 首选 MinerU（带 doc/page/block 定位符）；备选 Docling；扫描件补 PaddleOCR。
  • 架构图图片：多模态识读，source=llm，进入核验。
  • 输出统一 locator + Markdown 片段，进入 Chunk 向量化。

3.4 知识模型（图）

实体（节选）：Subsystem、Program、Paragraph、Copybook、Table、Dataset、Job、JobStep、Transaction、BusinessRule、Chunk。

关系（节选）：CALLS / XCTL / LINK、PERFORMS、READS / WRITES / UPDATES、RUNS / HAS_STEP / BINDS、ENTRY、IMPLEMENTED_BY、DESCRIBES。

统一元属性（节点与边）：

属性 取值 用途
source parser / llm / human 来源分级
confidence high / medium / low 展示与门禁
evidence file:line 或 locator 溯源
review_status pending / auto_passed / confirmed / rejected 可检索/可依据

4. 知识生成设计

4.1 编排

  • 外层流水线按「段落 → 程序 → 作业/交易 → 子系统」切任务；每任务独立 Agent 会话，可并行、可重跑。
  • Agent 运行时：PI（MIT）或等价 OpenAI 兼容 Agent；工具只读（图查询、读源码片段）。
  • 断网容器：只挂载任务所需只读源码与结构事实。

4.2 分层产出

层 输入 输出
L1 段落 段落源码 + PERFORM 邻居 段落功能说明
L2 程序 L1 + 文件/调用/作业事实 程序知识文档（模板见附录）
L3 作业/交易 L2 汇总 作业/交易说明、数据血缘摘要
L4 子系统 L3 + 聚类 子系统概览、耦合线索

4.3 程序知识文档模板（必含章节）

  1. 基本信息（类型、作业/交易、LOC、copybook）
  2. 功能概述
  3. 输入输出表（仅来自解析事实）
  4. 处理流程图（Mermaid，节点名必须存在于事实）
  5. 业务规则候选（编号、描述、出处、置信度）
  6. 迁移注意点 / 疑点
  7. 来源与审核状态

4.4 提示词约束（硬性）

  • 不得增删结构事实中的调用与文件访问。
  • 每条结论必须有 [file:start-end]；无出处不写。
  • 不确定标「待确认」；可疑代码进「疑点」。

5. 核验与人工确认设计

5.1 自动核验规则（MVP 清单）

编号 规则 失败处置
V-REL Mermaid/文档中的调用边必须存在于依赖图 入审核队列
V-IO 文档 IO 表与解析事实集合一致 入审核队列
V-EVD 引用行号落在文件真实行范围内 入审核队列
V-ID 实体名可在全文/图中解析 降置信或驳回草稿
V-DUP 疑点重复拼接/空实现等启发式 写入疑点区，不阻断

5.2 审核工作台

  • 队列排序：依赖图中心度 × 变更频率 × 历史缺陷（有则加权）。
  • 界面：左知识文档 / 右源码（跳行） / 下依赖子图。
  • 动作：确认、修改后确认、驳回（原因码）、转交；全量审计。
  • 反馈：驳回原因统计 → 反哺提示词与规则。

5.3 来源门禁

来源 可作迁移依据
parser 是
llm + auto_passed 参考；关键规则需 human
llm 未审核/失败 否（界面显著标注）
human 是

6. 知识存储设计

6.1 组件职责

组件 内容
Neo4j 依赖图、语义节点、Chunk 向量索引、标识符全文索引（whitespace，保护 ACCT-UPDATE）
PostgreSQL 用户权限、审核流、版本、流水线任务、核验结果、问答审计、已验证答案
MinIO 源码快照、原文、解析中间件、知识 MD、图快照
（备选）Milvus 若向量与图分离部署时承载多集合向量

图访问经 Repository 接口 抽象，查询模板使用 openCypher 公共子集，便于 AGE/Memgraph 替换（POC 压测后定稿）。

6.2 关键关系表（PostgreSQL）

  • t_kb_version：版本号、源码 commit、创建时间、操作者
  • t_pipeline_task：任务类型、状态、重试、产物路径
  • t_review_item / t_review_action：审核队列与留痕
  • t_verified_answer：指纹、场景、答案 JSON、status、kb_version（知识变更致 stale）
  • t_audit_log：问答/查询/工具调用

6.3 对象路径规范

kb-raw/{date}/{type}/...          # 原始
kb-derived/{kb_version}/ast/...   # 解析
kb-derived/{kb_version}/md/...    # 知识文档
kb-snapshot/{kb_version}/graph/   # 图导出

7. 服务层与接口设计

7.1 统一约定

  • Base：/api/v1
  • 响应：{ code, message, data, trace_id }
  • 鉴权：JWT + RBAC（研发 / 业务 / 治理员 / 管理员等）
  • 写操作仅流水线服务账号 + 审核写接口

7.2 核心 REST（本期）

7.3 Agent 工具（正式结论禁用自由 Text2Cypher）

工具 能力
search_knowledge 混合检索；默认仅已确认/自动核验通过
graph_query 参数化 Cypher 模板
read_source 指定文件行读取
query_cache / save_answer 三级分流长时记忆（与现网一致）

7.4 影响分析模板（示例）

  • IA-01：修改 Program → 写出 Dataset → 下游 Job/Program（≤3 跳）
  • IA-02：修改 Copybook 字段 → 引用 Program 列表
  • IA-03：修改 Transaction 入口 → 调用扇出
  • 动态未解析调用：必须在报告「风险提示」单独成节

8. 应用层设计

8.1 智能问答

  • GraphRAG：向量/全文 → 图扩展 → 必要时读源码 → 带出处与置信度作答。
  • 答案结构：是什么 / 为什么 / 怎么处理 + sources + caveats + 推理轨迹。
  • 指纹三级分流：exact 直出 / similar 参考复用 / miss 实时推理；复核沉淀闭环。

8.2 耦合度与解耦评估（本期深度：MVP）

  • 基于图算法（中心度、Louvain 聚类、扇入扇出）输出模块边界建议。
  • 报告字段：候选切分、跨边界调用数、共享 Dataset/Copybook、风险等级。
  • Demo 阶段可用预计算 + 简化指标；第 3 月补齐可交互评估页。

8.3 可视化

  • Demo：调用链/作业-程序-数据集子图（前端 + 简易图 API）。
  • 目标：对接 CBM Lens（只读注入；关闭其自动重索引）。

8.4 重构支撑（第 4 月试点）

  • 技术映射表（COBOL→Java 陷阱：截断 vs 四舍五入、REDEFINES、COMP-3 等）。
  • 生成带 【人工校验点 V-xx】 的 Java 骨架。
  • 等价性：至少规则级参数化单测样例；回放/并行列入试点外延清单。

9. 安全、合规与部署

9.1 私有化

  • 源码、文档、模型、向量全在行内隔离网；无外网出口。
  • 镜像与权重离线导入；关闭遥测与远程模型下载。

9.2 权限与审计

  • 对接行内统一认证（Demo 可用本地 JWT）。
  • 按子系统控制可见性（框架第 2 月落地）。
  • 问答、图查、审核、工具调用全量 trace_id 审计。

9.3 逻辑部署（4 个月目标拓扑）

节点 组件
GPU 推理 私有 LLM + Embedding（OpenAI 兼容，如 vLLM）
解析/生成 Worker codegraph 扩展、Agent 流水线（K8s Job/队列）
数据面 Neo4j、PostgreSQL、MinIO
应用面 API Gateway、FastAPI、Vue 门户
Demo 简化 单机 docker-compose 或内嵌回退存储

10. Demo（≤2 周）范围与验收

10.1 场景

以 CardDemo 利息计算（CBACT04C / INTCALC） 与 ATM 取款/余额 双场景演示。

10.2 必演示能力

  1. 源码/JCL/文档接入与解析事实入库（含作业—程序—数据集关联）。
  2. 生成程序知识文档（含规则 R1–R3 级示例）与出处跳转。
  3. 自动核验失败样例进审核队列；确认后可检索。
  4. 问答：利息如何计算、DEFAULT 利率回退；答案带来源行号。
  5. 影响分析：修改 CBACT04C 影响 ACCTDATA 及下游作业列表。
  6. 前端：问答台、治理台、知识管理、系统状态可切换 Mock/真实模型。

10.3 验收指标（Demo）

指标 目标
主路径可用性 上述 6 项端到端可演示，无阻断性缺陷
结构事实可复现 同一源码重复解析，关键边集合一致
问答抽样 约定 10 题中 ≥7 题「可参考」且出处正确
安全声明 展示私有化配置项与数据不落外网说明

11. 非功能需求

类别 指标（4 个月目标）
性能 CardDemo 全量解析 < 5 min；单次影响分析（≤3 跳）P95 < 3s
规模验证 POC 合成放大至约 100 万节点，记录 6 跳查询耗时
可用性 API 月度可用率目标 99%（试点环境）
