## 1. 排期原则（对齐设计 §1.2）

本排期只覆盖设计文档「纳入本周期」清单，不承诺「不纳入本周期」项：

| 设计纳入项 | 排期落点 |
| --- | --- |
| CardDemo / ATM 全链路 Demo（2 周内） | **W1–W2 → M0** |
| 解析扩展（JCL/SQL/CICS/常量传播）MVP | W1 启动，**W6 收齐** |
| 知识生成流水线（分层 Agent）+ 自动核验 | W2 雏形，**W6 分层 L1–L2 稳定** |
| 审核工作台 + 来源/置信度 | W2 可演示，**W10 专家闭环** |
| GraphRAG 问答、影响分析、基础可视化 | W2 可演示，**W14 深化** |

| 1 个试点模块 Java 骨架 + 规则级等价性样例 | **W15–W16** |

问答形态（设计 §2.3）：**前 6 周固定单一 Flow**；W11 起可切换 Agent 动态编排（同一套 Tools）。

## 4. 第 1–2 周：Demo 冲刺（设计 §10）

### 4.1 目标链路

`①接入 → ②解析(含 JCL) → ③生成/标注 → ④核验/审核 → ⑤入库 → ⑥问答/影响分析 → ⑦前端`

场景：**CardDemo（CBACT04C / INTCALC）** + **ATM 取款/余额**。

### 4.2 按层双周计划

| 天 | 设计层 | 工作项 | 产出 |
| --- | --- | --- | --- |
| D1 | 范围/§10 | 冻结 Demo 脚本 8–10 问；环境与账号 | 演示脚本 v1 |
| D2–D3 | §3 / §6 | COBOL+JCL 事实入库；ATM P0 适配器校验；图可查 | 事实 JSON + 子图 |
| D4–D5 | §4 / §5 | 程序知识文档模板（可半自动）；V-REL、V-IO；审核队列 | 样例 MD + 审核流 |
| D6–D7 | §7 / §8.1 / §8.2 | `/qa/ask`、`/impact/analyze`(IA-01)、出处跳转；前端联调 | 可点击包 |
| D8–D9 | §9 | Mock/真实模型双模式；一键启动；私有化说明 | README/启动脚本 |
| D10 | §10.3 | 彩排、清缺陷、预演 | **M0** |

### 4.3 M0 验收（设计 §10.2 / §10.3）

- [ ] INTCALC → CBACT04C → ACCTDATA/DISCGRP 关联可展示  
- [ ] 利息规则问答带来源行号；约定 10 题 ≥7 题可参考  
- [ ] 影响分析给出下游列表  
- [ ] 核验失败 → 人工确认 → 可检索  
- [ ] ATM ≥2 问可答  
- [ ] 双命令/一键可启动；主路径无阻断缺陷  
- [ ] 私有化与数据不出网说明可见  

### 4.4 Demo 不做（设计 §1.2 右侧 + §10 隐含）

全量千万行、运行时 SMF、模型微调、CBM 产品化、生产并行切流、完整 Java 重构、多国家数据主权深化。

## 9. 依赖、假设与风险

### 9.1 依赖与假设

1. M0 不依赖客户真实代码；CardDemo + ATM/`hf_data` 即可。  
2. 行内 GPU/模型未就绪时，W1–W4 可用 Mock/兼容接口；**W5 必须完成行内模型对比**。  
3. W7 前客户确认试点子系统，并提供 ≥2 名审核专家窗口。  
4. Neo4j Enterprise 未采购时，按设计 §6 启用 Community / PG+AGE 等退化方案，不阻 Demo/M1。

### 9.2 风险（对齐设计 §12）

| 风险 | 应对 | 缓冲 |
| --- | --- | --- |
| Demo 范围蔓延 | 严格 §4.4；争议当日 PM 裁决 | W1–W2 每日站会 |
| 模型 COBOL 弱 | 任务切小 + 强制注入结构事实 | W5 多模型并行 |
| 动态调用遗漏 | 常量传播 + 未解析强制曝光 | W3 关闭项 |
| 专家排期不足 | 只审中心度 Top-N | W9–W10 |
| 图性能不足 | 模板限跳数；物化热点路径 | W6/W14 |

W6、W10、W14 各预留 2–3 人日缺陷缓冲。
