# 通用检索方案

检索不包含测试工程名、程序名或三道验收题的专用分支。上传后的来源路径、程序标识、段落标题、系统、工程和版本元数据决定检索范围。

## 检索顺序

1. 识别完整标识符，区分 `ABC1` 和 `ABC12`；显式指定的当前对象优先，避免上一轮问题串入新的主题。
2. 程序名、文件名对应到当前有效文件。程序名可以与文件名不同；同名文件来自不同系统或工程时要求补充归属。
3. 对代码、文档、映射统一执行 BM25。COBOL 标识符保持完整，中文使用字符二元组，不依赖分词模型或外部服务。
4. 命中文件后，按段落、字段或操作定位原始正文中的相关上下文，附准确行号，补足切片覆盖空缺。补查结果只是查询证据，不保存成新切片，不改动 CodeGraph 的解析和切片规则。执行过切片清理的工程不启用原文补查。
5. 显式配置语义模型且索引记录的模型一致时，再融合语义召回。关键词与语义通道以排名融合，精确文件/结构定位优先；哈希向量不作为语义召回依据。可选服务失败时保留本地检索。
6. 证据按来源、位置和内容去重，限制同一文件占用的片段数量。代码指令优先于泛化的图谱摘要，图谱用于补充关系。没有有效命中时返回未覆盖，不补入哈希相似的无关代码。

默认的无模型 Agent、固定 Flow 和检索工具复用同一套检索。工具和合成上下文不再只截取片段前 200/280 字，减少关键语句被截掉的情况。演示模式展示命中的原文，不冒充语义理解结果。

## 自动更新

本地 BM25 索引随向量元数据的新增、删除和当前工程快照变化失效重建，不要求为新工程编写规则。上传新版本后只查询当前有效版本；切片清理后检索索引缓存失效。已复核答案引用失效的工程版本或被清理的工程时不再复用，新出现同名工程歧义时也不直接复用原来的无范围答案。新增代码和文档使用配置的同一个嵌入模型记录模型身份；旧哈希索引不会被当成新语义模型的索引。

## 验证边界

回归包含独立命名的多个工程、程序名与文件名不同、原切片未覆盖执行语句、新上传后立即查询、同名歧义、当前版本切换、清理、标识符边界、中文文档和查无资料，以及 Agent/Flow 最终证据顺序。

这些测试证明已覆盖的检索行为。没有语义模型时，同义改写、复杂业务含义和跨文件推理仍有限；实际业务准确率需另外准备代表性问题集验收。当前原文回补只对明确定位的代码文件启用，避免全库扫描原文造成大量噪声。
